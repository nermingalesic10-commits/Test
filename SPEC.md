# TARGET: Internship career journey

Choose the idea, person, interaction, and visual direction. The agent can help phrase and save your decisions after you approve them. The provided scope and review safeguards stay in place.

- **Thing:** Build a two-page internship and career-journey tracker: **Career Map** for a motivating path toward a desired role and **Applications** for internship/job entries. Keep the Pages front end static; an optional, separately deployed Cloudflare Worker can produce a reviewable role-title draft.
- **Audience:** Students and early-career job seekers ages 18–25 who want to organize applications and track the skills and milestones needed for their dream internship or job.
- **Requirements:** Provide a manual application tracker and a Career Map styled like a friendly game board. Include visible skill-progress cards and achievement badges. A visitor can navigate between pages, select an application or milestone for details, enter only a dream-role title, review and edit a seven-stop Worker draft, and explicitly accept it before it replaces the current in-browser map.
- **Guardrails:** User-approved scope exception: retain two static Pages and add a separate Cloudflare Worker using a Workers AI binding only for text-only dream-role draft generation. It must accept no job-post URL, résumé, company details, or personal data; retain no user records; use no browser key; allow only listed site/dev origins; rate-limit requests; label generated content as a draft; and never overwrite the map without an explicit accept action. Keep URL scraping/import, accounts, persistence, analytics, private data, and a backend data store as planned future work. Preserve examples and publishing setup. Work on this branch and wait for human review before any deployment, PR, merge, or publishing change.
- **Experience:** Make the site professional, colorful, and user-friendly. Applications and Career Map should feel coherent while presenting distinct purposes; the map should feel game-like and motivating through pathways, milestones, and badges without becoming childish or hard to scan. The role-draft experience must clearly distinguish a configured AI draft, a local example, and the existing fictional sample.
- **Test:** I can navigate between Applications and Career Map, add or inspect a sample manual application and its status, select a career milestone, and see related skill progress, completion state, achievement badge, and the standing rule's effect. With the local Worker preview or a configured Worker, I can enter a valid role title, receive a clearly labeled draft, edit it, accept it, and see only the in-browser map update; a URL, missing service, failed request, and rejected draft do not change the map. After I approve and merge, the same registered Pages URL works.
